# 地图编辑闭环增强 v1 设计规格书

## 1. 阶段定位

当前双向地图预览编辑器已经支持：

- 从 `data/maps.json` 和 `data/map_layouts/<map_id>.json` 生成编辑器预览。
- AI 修改地图布局或地图内容后，Godot 编辑器自动刷新。
- 在编辑器内拖动地图对象、出生点、障碍物，并保存回布局 JSON。
- 显示对象名称、类型颜色、对象列表和选中高亮。

本阶段目标是在现有能力上补齐“地图编辑闭环 v1”：让用户能更顺手地编辑已有元素、用模板新增常见地图元素，并用测试确认编辑器预览与运行时地图数据保持一致。

本阶段不负责编辑完整剧情正文。地图编辑器只创建和维护剧情入口，例如 `dialogue_id`、`quest_id`、`battle_id`、`target_map_id` 等引用字段。对白、任务、战斗、奖励和条件逻辑由后续独立剧情内容系统负责。

## 2. 范围

### 2.1 本阶段支持

- 选中对象、出生点、障碍物后，右侧 Dock 自动填充可编辑字段。
- 通过 Dock 修改对象坐标、交互半径、出生点坐标、障碍物位置和尺寸。
- 在 Dock 中用模板新增 NPC、出口、拾取物、战斗点、出生点和矩形障碍物。
- 新增玩法对象时写入 `data/maps.json`，新增布局字段时写入 `data/map_layouts/<map_id>.json`。
- 保存前保持现有“未保存修改”状态，避免用户以为已经写盘。
- 增加运行时一致性测试，确认 `DataRepository.get_map()` 合并后的地图数据与布局文件一致。

### 2.2 本阶段不支持

- 不编辑对白树正文。
- 不编辑任务链、任务奖励和复杂条件。
- 不编辑完整战斗配置。
- 不做字段级冲突合并。
- 不做 TileMap、导航网格或复杂多边形障碍编辑。
- 不把 `GeneratedMapPreview` 烘焙成正式 `.tscn` 内容。

## 3. 用户体验

### 3.1 属性编辑

当用户点击对象列表或选中预览节点时，Dock 自动进入对应编辑状态：

- 对象：显示 `object_id`、名称、类型、`x/y`、`radius`。
- 出生点：显示 `spawn_id`、`x/y`。
- 障碍物：显示 `obstacle_id`、`x/y/w/h`。

用户修改字段并点击应用后，预览立即重建或更新，文档进入未保存状态。点击保存后才写回 JSON。

### 3.2 模板新增

Dock 新增“新增元素”区域，用户选择类型并输入基础字段后创建模板。

NPC 模板写入 `data/maps.json`：

```json
{
  "id": "npc_new",
  "type": "npc",
  "name": "新人物",
  "dialogue_id": "dialogue_npc_new"
}
```

出口模板：

```json
{
  "id": "exit_to_next",
  "type": "exit",
  "name": "去下一处",
  "target_map_id": "next_map",
  "spawn_id": "start"
}
```

拾取物模板：

```json
{
  "id": "pickup_new",
  "type": "pickup",
  "name": "可拾取物",
  "effects": []
}
```

战斗点模板：

```json
{
  "id": "enemy_new",
  "type": "battle",
  "name": "敌人",
  "battle_id": "battle_enemy_new"
}
```

所有玩法对象同时在布局文件中写入：

```json
"objects": {
  "npc_new": {
    "position": {"x": 640, "y": 360},
    "radius": 48
  }
}
```

出生点只写入布局文件 `spawn_points`。矩形障碍物只写入布局文件 `obstacles`。

### 3.3 保存与刷新

- 新增或编辑后，Dock 显示未保存状态。
- 点击保存后，同时保存被修改的内容文档和布局文档。
- 如果 `data/maps.json` 或布局文件在外部被修改，继续沿用当前冲突策略：有未保存修改时不静默覆盖。
- 自动刷新开启时，外部 AI 修改仍会刷新预览；若当前本地有未保存布局修改，则不覆盖本地布局内存。

## 4. 架构设计

### 4.1 内容文档层

当前已有 `MapIndexDocument` 用于读取 `data/maps.json`。本阶段需要扩展或新增一个编辑能力较强的内容文档接口：

- 读取并保留 `data/maps.json` 的数组顺序和未知字段。
- 更新指定地图的 `objects` 数组。
- 新增对象时校验 `id` 不重复。
- 保存时只重写 `data/maps.json`。
- 记录 `dirty`、`loaded_hash` 和外部变化状态。

如果 `MapIndexDocument` 继续承担读索引职责，可以新增 `MapContentDocument` 负责写入，避免索引类变得过重。

### 4.2 布局文档层

`MapLayoutDocument` 继续负责 `data/map_layouts/<map_id>.json`：

- 更新对象位置和半径。
- 更新出生点坐标。
- 更新障碍物矩形。
- 新增对象布局、出生点和矩形障碍物。
- 保存布局文件并更新哈希。

### 4.3 插件 Dock

`MapPreviewPlugin` 扩展 Dock：

- 当前选择信息区：显示选中元素类型和编号。
- 属性编辑区：坐标、半径、尺寸输入。
- 新增元素区：类型选择、编号、名称、模板字段、创建按钮。
- 保存状态区：显示内容文档和布局文档是否有未保存修改。

Dock 不编辑复杂剧情正文，只生成引用字段。缺失的引用由后续内容引用校验器提示。

### 4.4 渲染与选择

`MapPreviewRenderer` 继续负责生成 `GeneratedMapPreview`。本阶段补齐选择回调：

- 对象、出生点、障碍物都可以反向填充 Dock。
- 拖动任意 handle 后，Dock 中的坐标字段同步更新。
- 创建新元素后自动选中新元素，方便立即微调。

## 5. 数据流

### 5.1 新增 NPC

1. 用户选择新增类型 `NPC`。
2. 输入 `id`、`name`，使用默认坐标和半径。
3. 插件向当前地图的 `objects` 数组追加 NPC 模板。
4. 插件向当前布局的 `objects.<id>` 写入位置和半径。
5. 插件重建预览并选中新 NPC。
6. 用户拖动或修改字段后点击保存。
7. `data/maps.json` 和当前布局文件写盘。

### 5.2 编辑障碍物

1. 用户选中矩形障碍物。
2. Dock 填入 `x/y/w/h`。
3. 用户修改尺寸并应用。
4. 插件更新布局内存并重建预览。
5. 点击保存后写回布局 JSON。

### 5.3 运行时一致性

1. 布局文件保存对象坐标、半径、出生点、障碍物和背景。
2. `DataRepository.get_map(map_id)` 合并玩法数据与布局数据。
3. 地图场景运行时使用合并后的数据生成对象和地形。
4. 自动测试确认合并结果与布局文件一致。

## 6. 错误处理

- 新增对象 `id` 为空：提示 `请输入对象编号。`
- 新增对象 `id` 重复：提示 `对象编号已存在：<id>`。
- 新增出生点 `id` 重复：提示 `出生点已存在：<id>`。
- 新增障碍物 `id` 重复：提示 `障碍编号已存在：<id>`。
- 坐标或尺寸非法：拒绝应用并提示具体字段。
- 保存内容时发现外部变化：提示用户重载或再次确认覆盖。
- 只保存布局成功但内容保存失败时：状态栏明确显示失败文件，避免误判。

## 7. 测试策略

### 7.1 自动化测试

- 内容文档新增对象：保留未知字段、保持其他地图不变、拒绝重复 id。
- 布局文档新增对象布局、出生点、障碍物。
- 属性编辑更新坐标、半径和矩形尺寸。
- `DataRepository.get_map()` 合并布局数据后，对象坐标、半径、出生点、障碍物和背景与布局文件一致。
- 非法输入和重复 id 返回明确错误。

### 7.2 手动验收

- 打开 `scenes/mountain_pass.tscn`。
- 新增一个 NPC，确认地图上立刻出现并自动选中。
- 拖动新 NPC，保存，检查两个 JSON 文件都更新。
- 新增一个出口和出生点，确认字段模板正确。
- 新增一个矩形障碍物，修改 `w/h`，保存后重开场景仍存在。
- 运行游戏，确认对象位置和障碍物与编辑器预览一致。

## 8. 后续阶段记录

### 8.1 下一阶段：内容引用校验器

目标是让 AI 或用户改 JSON 后，能快速知道哪些内容引用断了。

范围：

- 校验 `dialogue_id` 是否存在于 `data/dialogues.json`。
- 校验 `quest_id` 是否存在于 `data/quests.json`。
- 校验 `battle_id` 是否存在于战斗数据。
- 校验 `target_map_id` 和 `spawn_id` 是否存在。
- 校验拾取物 `effects` 引用的物品、flag 或任务是否有效。
- 在地图预览 Dock 中显示当前地图的引用错误，并允许定位到对象。

非目标：

- 不编辑对白、任务、战斗正文。
- 不自动修复复杂引用，只提供创建缺失模板的入口。

### 8.2 再下一阶段：剧情内容工作台

目标是把剧情正文编辑从地图编辑器中独立出来。

范围：

- 独立 Dock 或插件模块，面向 `data/dialogues.json`、`data/quests.json`、战斗数据和奖励数据。
- 从地图对象引用跳转到对应对白、任务或战斗。
- 对缺失的 `dialogue_id`、`quest_id`、`battle_id` 创建模板。
- 先支持对白和任务，再扩展战斗、奖励和条件。
- 提供内容级校验和预览，例如 NPC 对白树、任务阶段、完成效果。

边界：

- 地图编辑器负责“剧情入口在地图上的空间位置”。
- 剧情内容工作台负责“这个入口触发什么内容和后果”。

## 9. 验收标准

1. 用户可以在 Dock 中编辑对象、出生点和障碍物属性，预览立即更新。
2. 用户可以用模板新增 NPC、出口、拾取物、战斗点、出生点和障碍物。
3. 新增玩法对象写入 `data/maps.json`，对应坐标和半径写入当前布局文件。
4. 新增布局元素只写入当前布局文件。
5. 保存、重载、外部修改冲突状态清楚，不静默覆盖用户未保存编辑。
6. 运行时地图数据与编辑器布局数据一致，有自动测试覆盖。
7. 设计明确记录后续两个阶段：内容引用校验器、剧情内容工作台。
