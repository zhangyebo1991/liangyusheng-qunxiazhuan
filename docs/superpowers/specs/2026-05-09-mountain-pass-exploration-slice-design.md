# 山道探索垂直切片设计

日期：2026-05-09
项目：liangyusheng-qunxiazhuan
目标引擎：Godot 4.6

## 目标

下一阶段创建“山道探索垂直切片”，把当前基础框架推进到一段可以从头到尾操作的 3 到 5 分钟武侠探索体验。

本切片必须验证真实地图探索，而不是文本菜单或格子移动。玩家应能在正俯视 2D 山道地图中使用 WASD 连续移动，靠近 NPC 交谈，接取任务，触发战斗，回到地图交任务，获得奖励，并通过存档恢复地图状态。

## 范围

本阶段包含：

- 正俯视 2D 山道地图。
- `TileMapLayer` 地形和碰撞。
- `CharacterBody2D` 主角控制器。
- WASD 像素级连续移动。
- 摄像机跟随。
- 简易像素主角、NPC 和敌人图形。
- 基础四向站立与移动动画。
- 靠近后按 E 交互。
- 鼠标点击 NPC、敌人触发对象和 UI 按钮。
- 一条“山道试剑”任务闭环。
- 独立战斗场景，战斗结束后返回山道。
- 地图对象状态、玩家坐标、任务进度和奖励数据的存档恢复。
- 地图对象由 JSON 配置生成。

## 不做范围

本阶段不做：

- 格子移动。
- 点击地面自动寻路。
- 多地图。
- 背包界面。
- 角色面板。
- 完整死亡惩罚。
- 正式美术。
- 完整战斗规则。
- 商店、装备、队友招募或复杂剧情分支。

## 架构

项目继续保持“领域逻辑、系统流程、场景表现”分层。

- `scripts/domain/` 保存地图对象状态、任务结果和可序列化数据结构，不依赖 Godot 场景节点。
- `scripts/systems/` 保存地图数据读取、交互对象生成、交互处理、任务流程、战斗流程和存档流程。
- `scripts/core/` 保存全局状态、场景切换、事件分发和输入动作约定。
- `scripts/scenes/` 保存主角控制器、山道场景脚本、NPC 节点脚本、敌人触发点脚本和 UI 脚本。
- `data/` 保存 `maps.json` 以及任务、对话、角色、物品和武学数据。
- `scenes/` 保存山道地图场景、战斗场景、主菜单和启动场景。

山道地形和碰撞由 Godot 场景中的 `TileMapLayer` 维护。NPC、敌人触发点、奖励点和交互对象由 `data/maps.json` 配置，并由地图对象生成器在场景启动时生成。这样可以让地图美术和内容配置分离，便于后续新增地图。

## 关键组件

### 输入动作

输入统一通过 Godot `InputMap` 配置，不在业务脚本中硬写具体按键。

第一版动作：

- `move_up`：W。
- `move_down`：S。
- `move_left`：A。
- `move_right`：D。
- `interact`：E。
- `confirm`：Enter 和 Space。
- `cancel`：Esc。

本阶段预留手柄输入扩展，但不实现手柄适配。

### 主角控制器

主角使用 `CharacterBody2D`。主角控制器负责：

- 读取移动输入。
- 计算连续移动速度。
- 调用 Godot 物理移动。
- 记录朝向。
- 驱动四向站立和移动动画。
- 维护当前最近可交互对象。
- 向场景脚本报告玩家坐标变化。

主角控制器不直接修改任务、战斗或存档。它只发出交互意图，由交互系统和场景脚本处理。

### 地图对象生成器

地图对象生成器读取 `maps.json` 中指定地图的对象列表，生成对应运行时节点。

对象类型包括：

- `npc`：NPC，可交谈，可触发任务。
- `battle_trigger`：战斗触发点，进入范围后切换到战斗场景。
- `reward`：奖励点，第一版主要通过任务奖励使用。
- `exit`：地图出口，本阶段只预留结构。

生成器需要跳过已解决或已隐藏的地图对象。例如战斗胜利后，敌人触发点应记录为已解决，读档后不再生成。

### 交互系统

交互系统统一处理键盘和鼠标交互。

规则：

- 玩家靠近 NPC 或交互对象时显示交互提示。
- 按 E 时触发距离最近的可交互对象。
- 鼠标点击对象时，如果玩家在范围内则触发交互。
- 鼠标点击对象时，如果玩家不在范围内，则显示“距离太远”提示。
- 鼠标不触发地面移动。
- 如果多个对象重叠，优先选择距离玩家最近的对象。

### 山道场景

山道场景负责装配探索切片：

- 加载 `mountain_pass` 地图配置。
- 创建主角并设置出生点或读档坐标。
- 启动摄像机跟随。
- 生成 NPC 和战斗触发点。
- 显示任务摘要、交互提示和短消息。
- 处理任务流程与对话流程。
- 触发战斗并在战斗结束后恢复地图状态。

山道场景可以调用系统层服务，但不应把任务规则、奖励规则和存档序列化规则写死在场景脚本中。

## 玩法流程

第一版流程在一张山道地图内完成。

1. 玩家从主菜单选择“开始新游戏”。
2. 游戏进入山道入口，主角出现在默认出生点。
3. 玩家使用 WASD 连续移动，摄像机跟随主角。
4. 玩家靠近青衫客，界面显示“按 E 与青衫客交谈”。
5. 玩家按 E 或用鼠标点击青衫客，打开对话框。
6. 青衫客提示前方有强人拦路，并引出任务“山道试剑”。
7. 任务状态变为进行中，左上角显示任务摘要。
8. 玩家继续向山道前方移动。
9. 玩家进入敌人触发范围后，切换到独立战斗场景。
10. 战斗场景中玩家可使用基础剑法完成战斗。
11. 战斗胜利后返回山道，敌人触发点标记为已解决。
12. 玩家回到青衫客处交任务。
13. 青衫客发放奖励，例如小还丹和基础武学熟练度。
14. 任务状态变为已完成，任务摘要更新。
15. 存档记录当前地图、玩家坐标、任务状态、已解决对象和奖励数据。

战斗失败第一版不做死亡流程。失败后返回山道入口，并显示“气血不支，暂退数步”。任务保持进行中，玩家可以再次挑战。

## 数据设计

新增 `data/maps.json`，只负责地图对象配置，不负责绘制地形。

地图记录包含：

- 地图编号。
- 地图名称。
- 默认出生点。
- 地图对象列表。
- 出口结构预留。

地图对象包含：

- 对象编号。
- 对象类型。
- 显示名称。
- 位置。
- 交互半径。
- 关联角色编号。
- 关联对话编号。
- 关联任务编号。
- 关联敌人编号。
- 关联奖励。

示例结构：

```json
[
  {
    "id": "mountain_pass",
    "name": "山道",
    "spawn_position": {"x": 160, "y": 320},
    "objects": [
      {
        "id": "npc_qingshanke",
        "type": "npc",
        "name": "青衫客",
        "actor_id": "qingshanke",
        "position": {"x": 360, "y": 280},
        "radius": 56,
        "dialogue_id": "mountain_pass_intro",
        "quest_id": "quest_mountain_trial"
      },
      {
        "id": "enemy_bandit_gate",
        "type": "battle_trigger",
        "name": "山道强人",
        "actor_id": "bandit_01",
        "position": {"x": 720, "y": 260},
        "radius": 48,
        "quest_id": "quest_mountain_trial"
      }
    ]
  }
]
```

现有 `actors.json`、`dialogues.json`、`quests.json`、`items.json` 和 `martial_arts.json` 需要补充山道切片所需内容。所有玩家可见文本必须使用中文。

## 存档设计

`GameState` 和 `SaveSystem` 需要支持真实地图状态。

存档应包含：

- 当前地图编号。
- 玩家坐标。
- 当前任务状态。
- 已解决地图对象编号列表。
- 队伍成员。
- 背包物品。
- 奖励领取状态。
- 版本号。

读档规则：

- 如果地图编号存在，则进入对应地图。
- 如果地图编号不存在，则回到 `mountain_pass` 默认出生点。
- 如果玩家坐标非法，则回到当前地图默认出生点。
- 已解决对象不再生成。
- 已完成任务不再重复发放奖励。

## 输入、交互与界面

第一版 UI 只保留必要内容：

- 左上角任务摘要。
- 底部交互提示。
- 底部短消息。
- 对话框。
- 战斗场景按钮。
- 任务完成奖励提示。

对话框显示：

- 说话人名称。
- 当前对白文本。
- 继续按钮。

任务摘要显示：

- 未接任务时不显示或显示当前目标为空。
- 进行中显示“山道试剑：击退前方强人”。
- 可交付显示“山道试剑：回去向青衫客复命”。
- 已完成显示“山道试剑：已完成”。

本阶段不做背包界面和角色面板，但奖励必须进入队伍数据和存档数据。

## 战斗衔接

战斗触发后切换到独立战斗场景。进入战斗时需要传入：

- 敌人角色编号。
- 来源地图编号。
- 来源地图对象编号。
- 玩家进入战斗前坐标。
- 关联任务编号。

战斗结束后返回山道，并带回：

- 胜利或失败。
- 来源地图对象编号。
- 任务进度变化。
- 奖励领取状态。

战斗场景不直接修改山道节点。山道场景根据战斗结果更新地图对象状态。

## 错误处理

地图数据或内容数据配置错误时，游戏不应黑屏、卡死或进入不可操作状态。

错误处理规则：

- `maps.json` 缺失：进入山道空对象状态，并输出 Godot 错误日志。
- 地图编号不存在：回到 `mountain_pass` 默认出生点。
- NPC 缺少对话编号：对象仍生成，交互时显示“此人暂时无话可说”。
- 战斗触发点缺少敌人编号：不进入战斗，显示“此处事件尚未准备好”，并输出错误日志。
- 奖励物品编号不存在：任务仍可完成，跳过无效奖励并输出错误日志。
- 读档坐标非法：回到当前地图默认出生点。
- 战斗返回数据缺少来源对象编号：返回地图，但不清除任何敌人触发点，并输出错误日志。

## 测试

逻辑测试继续使用 Godot 无头脚本运行。

需要覆盖：

- `maps.json` 可以加载。
- 可以按地图编号读取 `mountain_pass`。
- 地图对象生成器能识别 NPC 和战斗触发点。
- 任务“山道试剑”可以从未开始、进行中、可交付、已完成流转。
- 战斗胜利后可以标记敌人触发点已解决。
- 存档可以保存和恢复当前地图、玩家坐标、任务状态、已解决对象和奖励数据。
- 鼠标点击远距离对象不会触发交互。
- 缺失内容编号不会导致测试运行崩溃。

场景验收需要人工或后续自动化验证：

- 从主菜单开始新游戏进入山道。
- WASD 可连续移动。
- 主角不会穿过障碍。
- 摄像机跟随主角。
- 靠近青衫客显示交互提示。
- E 键能交谈。
- 鼠标点击青衫客能交谈。
- 接任务后进入敌人区域会切到战斗场景。
- 战斗胜利后返回山道。
- 胜利后敌人触发点被清除。
- 回青衫客处可以完成任务。
- 奖励进入队伍数据。
- 存档后重新进入可以恢复地图、坐标和任务进度。

## 验收标准

本阶段完成后，玩家应能完成一段完整操作链：

主菜单开始新游戏，进入山道，移动到青衫客旁边，接取山道试剑，走到前方触发战斗，胜利后回到山道，回青衫客处交任务，获得奖励，保存并恢复任务进度。

验收标准不是完整游戏，而是第一段可玩的武侠探索闭环。后续地图、剧情、战斗深度和正式美术应在这个闭环验证后继续扩展。

## 实现约束

- 所有可以用中文写的地方必须使用中文。
- 代码标识符、Godot API、路径、配置键和命令可以保留英文。
- 不引入外部插件。
- 不把 Godot 引擎二进制提交到仓库。
- 逻辑优先写测试，再实现。
- 地图对象数据必须能被测试覆盖。
- 场景脚本只负责展示、输入和连接系统，不承载长期规则。
