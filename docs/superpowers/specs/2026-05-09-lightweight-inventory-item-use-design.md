# 轻量背包与物品使用切片设计

日期：2026-05-09
项目：liangyusheng-qunxiazhuan
目标引擎：Godot 4.6

## 目标

下一阶段创建“轻量背包与物品使用切片”，让当前探索和任务闭环中的奖励变成玩家看得见、用得上的反馈。

本阶段不追求完整 RPG 菜单。核心验证点是：任务奖励、初始物品、背包显示、消耗品使用、气血变化和存档恢复能否在现有地图探索结构中稳定运作。

## 范围

本阶段包含：

- 新增 `I` 键打开和关闭地图内背包面板。
- 背包面板显示物品名称、数量、类型和描述。
- 支持使用 `consumable` 类型物品。
- 第一版可使用物品为“小还丹”。
- 使用物品后减少背包数量，数量归零后从背包显示中隐藏。
- 使用成功后显示短消息，例如“服下小还丹，气血恢复。”
- 背包数量、气血和最大气血可存档和读档恢复。
- 任务奖励继续进入 `GameState.party.inventory`，并能在背包中看到。

本阶段不做：

- 装备界面。
- 商店买卖。
- 物品排序、分类和拖拽。
- 多角色选择用药。
- 战斗中使用物品。
- 复杂角色属性面板。
- 完整状态异常系统。

## 推荐方案

采用地图内轻量背包面板。

玩家在山道和山脚村镇中按 `I` 打开背包。背包作为 HUD 的一个面板显示在当前地图上，不切换到独立场景。这样能复用现有地图、HUD、存档和任务结构，同时避免提前引入菜单栈、暂停系统和复杂导航。

物品使用规则放在系统层，不写进 HUD。HUD 只负责显示背包内容和发出“使用物品”意图，具体校验、效果应用和扣除数量由 `InventorySystem` 处理。

## 架构

项目继续保持“领域逻辑、系统流程、场景表现”分层。

- `scripts/domain/party_state.gd` 保存队伍成员和背包数量。
- `scripts/domain/item_record.gd` 保存物品资料和效果数据。
- `scripts/systems/inventory_system.gd` 处理物品使用规则。
- `scripts/core/game_state.gd` 保存队伍、任务、地图、标记、气血和最大气血。
- `scripts/scenes/hud.gd` 显示背包面板、物品列表和按钮。
- `scripts/scenes/map_screen_base.gd` 统一接入背包开关、物品使用结果和 HUD 刷新。
- `data/items.json` 保存物品类型、描述和效果。
- `tests/` 保存 GDScript 逻辑测试。

## 关键组件

### PartyState

`PartyState` 已经拥有 `members` 和 `inventory`。本阶段扩展以下背包方法：

- `get_item_count(item_id)`：返回物品数量。
- `has_item(item_id, amount = 1)`：判断背包中是否有足够数量。
- `remove_item(item_id, amount = 1)`：扣除物品，成功返回 `true`，数量不足或参数无效返回 `false`。

`PartyState` 只管理数量，不判断物品类型、效果或使用条件。

### ItemRecord

`ItemRecord` 继续读取 `id`、`name`、`type`、`description` 和 `value`，新增 `effects` 字段。

第一版效果结构：

```json
{
  "id": "herb_small",
  "name": "小还丹",
  "type": "consumable",
  "description": "恢复少量气血。",
  "value": 30,
  "effects": {
    "heal_hp": 30
  }
}
```

`effects` 是字典。第一版只支持 `heal_hp`，后续可以扩展 `recover_mp`、`cure_status` 或临时增益。

### InventorySystem

新增 `scripts/systems/inventory_system.gd`，负责物品使用。

主要接口：

- `use_item(game_state, item_id)`：尝试使用物品，返回结果字典。

结果字典包含：

- `success`：是否成功使用。
- `message`：给 HUD 显示的中文短消息。
- `item_id`：物品编号。
- `remaining`：使用后的剩余数量。

规则：

- 物品编号为空时失败。
- 背包数量不足时失败。
- 物品资料不存在时失败。
- 非 `consumable` 类型时失败。
- 消耗效果缺失或无效时失败。
- 气血已满时失败，不扣物品。
- 成功时在校验通过后扣除 1 个物品并应用效果；如果扣除失败，不应用效果。

### GameState

`GameState` 新增轻量角色资源：

- `hero_hp`
- `hero_max_hp`

新游戏默认气血为满值。第一版只管理主角气血，不创建完整角色属性面板，也不引入多队友用药选择。

建议方法：

- `restore_hero_hp(amount)`：恢复主角气血，不能超过 `hero_max_hp`，返回实际恢复值。
- `is_hero_hp_full()`：判断气血是否已满。

`GameState.to_dictionary()` 和 `from_dictionary()` 需要保存和恢复 `hero_hp` 与 `hero_max_hp`。旧存档缺少字段时使用默认满气血。

### HUD 背包面板

`hud.gd` 新增背包面板。第一版使用 Godot 原生控件，不引入额外 UI 框架。

面板内容：

- 标题：“背包”。
- 空背包提示：“背包空空如也。”
- 每个物品显示名称、数量、类型和描述。
- `consumable` 类型物品显示“使用”按钮。
- 非消耗品显示为不可使用状态，或点击后显示“此物暂时不能使用。”
- 关闭按钮，或再次按 `I` 关闭。

HUD 不直接修改 `GameState.party.inventory`。点击“使用”后，把物品编号交给地图场景或系统层处理，再由场景刷新 HUD。

### MapScreenBase

`map_screen_base.gd` 统一接入背包行为：

- 监听 `inventory` 输入动作。
- 调用 HUD 打开或关闭背包面板。
- 在打开时合并 `GameState.party.inventory` 和 `DataRepository.get_item()` 生成显示列表。
- 接收 HUD 的使用物品请求。
- 调用 `InventorySystem.use_item(GameState, item_id)`。
- 显示结果消息。
- 使用成功或失败后刷新背包列表。

山道和山脚村镇继承该行为，不需要分别实现背包逻辑。

## 玩家流程

目标流程：

1. 玩家从主菜单开始新游戏，进入山道。
2. 新游戏时背包已有 1 个小还丹。
3. 玩家完成“山道试剑”，获得额外小还丹。
4. 玩家按 `I` 打开背包。
5. 背包显示“小还丹 x2”和物品描述。
6. 玩家点击“使用”。
7. 若气血未满，小还丹数量减少，气血恢复，HUD 显示“服下小还丹，气血恢复。”
8. 若气血已满，小还丹不减少，HUD 显示“气血已满。”
9. 玩家存档后读档，背包数量和气血保持正确。
10. 玩家在山脚村镇也可以打开同一个背包面板。

## 输入与界面

新增输入动作：

- `inventory`：I。

现有输入保持不变：

- WASD 连续移动。
- E 键交互。
- 鼠标点击 NPC、告示牌、出口对象和 UI 按钮。
- Enter / Space 确认。
- Esc 取消。

背包打开后第一版不暂停世界，也不禁止移动。玩家可以再次按 `I`、按关闭按钮或使用鼠标关闭面板。

## 数据设计

`data/items.json` 增加 `effects` 字段。

第一版物品：

- `herb_small`：`consumable`，效果为恢复气血。
- `iron_sword`：`weapon`，保留为不可使用物品，用于验证非消耗品提示。

`DataRepository.get_item(item_id)` 继续按编号读取物品。不存在的物品编号返回空字典，由 `InventorySystem` 转换成用户可见错误消息。

## 存档设计

现有 `SaveSystem` 继续保存 `GameState.to_dictionary()` 的结果。

本阶段需要保存：

- 队伍成员。
- 背包物品数量。
- 当前任务状态。
- 当前地图编号。
- 玩家坐标。
- 地图对象状态。
- 奖励领取状态。
- 标记数据。
- 主角气血。
- 主角最大气血。

读档规则：

- 背包数量按存档恢复。
- 气血缺失时回退为默认满气血。
- 气血大于最大气血时钳制到最大气血。
- 背包里存在未知物品编号时保留数量，但 HUD 显示“未知物品”，并禁止使用。

## 错误处理

错误处理规则：

- 背包为空：显示“背包空空如也。”
- 物品编号不存在：显示“此物品资料缺失。”
- 数量不足：显示“背包中没有此物。”
- 非消耗品：显示“此物暂时不能使用。”
- 气血已满：不扣数量，显示“气血已满。”
- 消耗效果缺失或无效：不扣数量，显示“此物暂时不能使用。”
- 背包扣除失败：不应用效果，显示“背包中没有此物。”
- 读档气血异常：钳制到 `0..hero_max_hp` 范围内。

## 测试

逻辑测试继续使用 Godot 无头脚本运行。

需要覆盖：

- `PartyState` 能增加、减少和查询物品。
- `PartyState.remove_item()` 在数量不足时失败，且不会扣成负数。
- `ItemRecord` 能读取 `effects`。
- `InventorySystem` 能成功使用小还丹，恢复气血并扣除数量。
- 气血已满时使用小还丹失败，且不扣数量。
- 物品不存在时使用失败，且不扣数量。
- 非消耗品使用失败，且不扣数量。
- 数量不足时使用失败。
- `GameState` 存档和读档能恢复背包数量、气血和最大气血。
- 旧存档缺少气血字段时能安全读入默认值。

场景验收需要人工或后续自动化验证：

- 按 `I` 可以打开和关闭背包。
- 新游戏背包能看到小还丹。
- 完成山道任务后背包数量增加。
- 气血未满时可以使用小还丹，数量减少。
- 气血已满时不能浪费小还丹。
- 在山道和山脚村镇都能打开背包。
- 存档后读档，背包数量和气血保持正确。

## 验收标准

本阶段完成后，玩家可以在地图中打开背包，看到已有小还丹和任务奖励，使用小还丹恢复气血，并通过存档恢复背包数量和气血状态。

本阶段不是完整背包系统。它只验证奖励可见化、消耗品使用和存档闭环，为后续商店、装备、战斗中用药和角色属性界面打基础。
