# 基础回合战斗与武学成长切片设计

日期：2026-05-09
项目：liangyusheng-qunxiazhuan
目标引擎：Godot 4.6

## 目标

下一阶段创建“基础回合战斗与武学成长切片”，把当前山道强人战从一次性结算推进到一场可操作、可失败、可成长的最小回合战斗。

本阶段的核心验证点是：玩家能在战斗中逐回合选择行动，敌人能反击，背包消耗品能在战斗中生效，战斗胜负能正确回流地图和任务，胜利后能记录基础剑法熟练度，并通过存档恢复气血、背包和成长数据。

## 范围

本阶段包含：

- 战斗中显示主角和敌人的气血。
- 玩家每回合选择“基础剑法”、“小还丹”或“暂退”。
- 敌人每回合自动普通攻击。
- “基础剑法”造成伤害并写入战斗日志。
- 战斗中可使用“小还丹”，复用 `InventorySystem` 扣除背包数量并恢复气血。
- 使用物品失败时显示中文原因，例如“背包中没有此物。”或“气血已满。”。
- 山道强人战需要调整为至少承受一次主角攻击，不再被当前基础剑法一击击败。
- 胜利后清除来源战斗触发点，并把关联任务推进到可交付状态。
- 胜利后记录 `basic_sword` 熟练度 `+1`。
- 失败或暂退后返回地图，不清除敌人触发点，不推进任务。
- 主角剩余气血、背包数量和武学熟练度可存档和读档恢复。

本阶段不做：

- 多名队友参战。
- 多个敌人参战。
- 复杂内力、轻功、状态异常或连击。
- 装备属性参与战斗。
- 多招式搭配。
- 敌人复杂 AI。
- 战斗动画和正式美术。
- 角色等级、经验条或完整角色面板。

## 推荐方案

采用轻量回合战斗切片，优先做“战斗规则可测试，战斗界面可替换”。

当前项目已经具备两张地图、任务闭环、背包、物品使用和存档。继续铺第三张地图会扩大内容面积，但不会解决战斗过浅的问题。下阶段应先让山道强人战成为真正的 RPG 交互：玩家做选择、承受反击、消耗物品、胜利后得到成长反馈。

成长第一版采用武学熟练度，不采用角色等级。武侠题材中“基础剑法熟练度提升”比通用经验更贴合，并且能直接服务后续多武学系统。熟练度第一版只记录和显示，不反向影响伤害，避免过早引入数值平衡。

## 架构

项目继续保持“领域逻辑、系统流程、场景表现”分层。

- `scripts/domain/battle_state.gd` 保存一场战斗的运行时状态。
- `scripts/systems/combat_system.gd` 处理回合行动、伤害、敌人反击、胜负和日志。
- `scripts/systems/inventory_system.gd` 继续处理消耗品校验、扣除和恢复气血。
- `scripts/core/game_state.gd` 保存主角气血、背包、任务、地图状态和武学熟练度。
- `scripts/scenes/battle_screen.gd` 显示气血、按钮和日志，并把玩家意图交给系统层。
- `data/actors.json` 保存敌人气血和基础属性，山道强人需要支持至少 2 回合战斗验证。
- `data/martial_arts.json` 保存武学静态资料和熟练度奖励配置。
- `tests/` 保存 GDScript 逻辑测试。

战斗界面不直接计算伤害，不直接扣背包，不直接推进任务。它只根据按钮触发行动，再用系统返回的结果刷新 UI 或回到地图。

## 关键组件

### BattleState

新增 `scripts/domain/battle_state.gd`，作为战斗运行时状态。

建议字段：

- `hero_id`
- `enemy_id`
- `hero_hp`
- `hero_max_hp`
- `enemy_hp`
- `enemy_max_hp`
- `round`
- `is_finished`
- `victory`
- `log`
- `source_map_id`
- `source_object_id`
- `quest_id`

`BattleState` 只保存状态和序列化，不读取数据仓库，也不操作 Godot 节点。

### CombatSystem

`CombatSystem` 从当前 `resolve_duel(attacker, defender, martial_art)` 扩展为回合规则层。

建议接口：

- `create_battle(game_state, context, repository)`：根据战斗上下文和数据仓库创建 `BattleState`。
- `use_martial_art(battle_state, attacker, defender, martial_art)`：处理主角招式行动。
- `enemy_attack(battle_state, enemy, hero)`：处理敌人普通攻击。
- `resolve_player_attack(battle_state, game_state, martial_art_id)`：执行玩家攻击和必要的敌人反击。
- `resolve_player_item(battle_state, game_state, item_id)`：执行物品使用和必要的敌人反击。
- `resolve_retreat(battle_state)`：处理暂退。

伤害第一版仍使用现有公式：

```text
damage = max(1, attacker.attack + martial_art.power - defender.defense)
```

敌人普通攻击第一版使用：

```text
damage = max(1, enemy.attack - hero_defense)
```

如果主角攻击后敌人气血归零，不再触发敌人反击。

山道强人第一版应调整到不会被当前基础剑法一击击败。实现可以提高 `bandit_01.hp`，也可以在新回合战斗中使用战斗状态的敌人气血覆盖值；推荐直接调整内容数据，让数据和场景体验一致。

### BattleScreen

`battle_screen.gd` 替换当前“一次点击后立即返回”的流程。

界面第一版显示：

- 标题：敌人名称。
- 主角气血：`当前 / 最大`。
- 敌人气血：`当前 / 最大`。
- 回合日志。
- 按钮：“基础剑法”、“小还丹”、“暂退”。

按钮行为：

- “基础剑法”：调用战斗系统执行主角攻击。
- “小还丹”：调用战斗系统执行战斗中用药，用药规则复用 `InventorySystem`。
- “暂退”：结束战斗并返回来源地图。

战斗结束后，界面可以短暂显示最终日志，然后通过 `call_deferred()` 回到来源地图场景。

### GameState

`GameState` 新增武学熟练度进度：

```text
martial_proficiency: {"basic_sword": 0}
```

建议方法：

- `add_martial_proficiency(martial_art_id, amount)`：增加武学熟练度，返回增加后的值。
- `get_martial_proficiency(martial_art_id)`：读取当前熟练度。
- `apply_battle_result(result)`：继续处理地图对象和任务回流，并在胜利时写入熟练度奖励。

`GameState.to_dictionary()` 和 `from_dictionary()` 需要保存和恢复 `martial_proficiency`。旧存档缺少字段时使用空字典。

### MartialArtRecord

`MartialArtRecord` 保留现有字段，并读取可选字段：

- `proficiency_reward`

第一版 `basic_sword` 的 `proficiency_reward` 为 `1`。如果字段缺失，默认胜利奖励为 `1`，避免旧数据导致无成长反馈。

## 玩家流程

1. 玩家在山道触发强人战，进入战斗场景。
2. 战斗界面显示双方气血、回合日志和三个按钮。
3. 玩家点击“基础剑法”。
4. 主角造成伤害，日志显示出招和伤害。
5. 如果敌人未倒下，敌人普通攻击主角，日志显示反击和伤害。
6. 玩家可以继续攻击、使用小还丹或暂退。
7. 使用小还丹成功时扣除 1 个小还丹并恢复主角气血；如果敌人未倒下，敌人随后反击。
8. 使用小还丹失败时只显示原因，不扣物品，也不消耗回合。
9. 敌人气血归零时战斗胜利，清除山道强人触发点，山道试剑进入可交付状态，基础剑法熟练度提升。
10. 主角气血归零时战斗失败，返回山道入口，敌人触发点保留，任务保持进行中。
11. 玩家暂退时返回地图，不清除敌人触发点，不推进任务。
12. 存档后读档，主角气血、背包数量、任务状态、已解决对象和武学熟练度保持正确。

## 输入与界面

战斗场景继续使用鼠标点击按钮。第一版不要求键盘快捷键。

按钮：

- “基础剑法”
- “小还丹”
- “暂退”

日志需要使用中文，并包含以下信息：

- 当前回合。
- 主角造成的伤害。
- 敌人造成的伤害。
- 小还丹使用成功或失败原因。
- 胜利、失败或暂退结果。
- 胜利后的熟练度提升。

## 战斗结果规则

胜利：

- `victory = true`
- 主角剩余气血写回 `GameState.hero_hp`。
- 来源对象编号存在时，标记为已解决。
- 关联任务编号存在时，任务进入可交付状态。
- `basic_sword` 熟练度增加。
- 返回来源地图。

失败：

- `victory = false`
- 不清除来源对象。
- 不推进任务。
- 主角气血钳制到至少 `1`，避免回地图后处于不可操作状态。
- 返回山道入口或战斗上下文指定的失败返回点。

暂退：

- 视为失败回流。
- 不清除来源对象。
- 不推进任务。
- 主角当前气血写回 `GameState.hero_hp`，但至少为 `1`。

## 存档设计

现有 `SaveSystem` 继续保存 `GameState.to_dictionary()` 的结果。

本阶段新增保存：

- `martial_proficiency`

继续保存：

- `party`
- `quests`
- `map_state`
- `flags`
- `hero_hp`
- `hero_max_hp`

读档规则：

- 缺少 `martial_proficiency` 时使用空字典。
- 熟练度值小于 0 时钳制为 0。
- 气血仍按现有规则钳制到 `0..hero_max_hp`。
- 旧存档可以继续读入。

## 错误处理

错误处理规则：

- 战斗上下文缺少敌人编号：默认使用 `bandit_01`。
- 敌人数据缺失：显示“敌人资料缺失。”，允许暂退返回地图。
- 主角数据缺失：显示“主角资料缺失。”，允许暂退返回地图。
- 武学数据缺失：禁用“基础剑法”或显示“武学资料缺失。”。
- 小还丹不足：显示“背包中没有此物。”，不消耗回合。
- 气血已满时用药：显示“气血已满。”，不扣物品，不消耗回合。
- 战斗结果缺少来源对象：可以返回地图，但不清除任何触发点，并输出错误日志。
- 返回地图编号缺失或无效：回到 `mountain_pass`。

## 测试

逻辑测试继续使用 Godot 无头脚本运行。

需要覆盖：

- `BattleState` 能保存双方气血、回合数和日志。
- 创建战斗时能从 `GameState` 和战斗上下文读取主角气血、敌人和来源对象。
- 玩家基础剑法能扣敌人气血。
- 山道强人配置应确保基础剑法不会一击结束战斗。
- 敌人未倒下时会反击并扣主角气血。
- 敌人倒下时不会再反击。
- 小还丹在战斗中可恢复气血并扣背包。
- 气血已满时使用小还丹失败且不扣物品。
- 小还丹不足时使用失败且不消耗回合。
- 暂退不清除敌人触发点，不推进任务。
- 失败不清除敌人触发点，不推进任务，并把主角气血钳制到安全值。
- 胜利后 `GameState.apply_battle_result()` 清除对象、推进任务、增加武学熟练度。
- 存档读档能恢复 `martial_proficiency`。

场景验收需要人工或后续自动化验证：

- 从山道触发强人战后进入战斗场景。
- 战斗界面显示双方气血。
- 点击“基础剑法”后，敌人气血下降并出现日志。
- 敌人未倒下时会反击，主角气血下降。
- 主角气血未满且背包有小还丹时，可以在战斗中用药。
- 气血已满或没有小还丹时，用药不会错误扣除物品。
- 战斗至少可以经历 2 个回合选择。
- 胜利后返回山道，强人触发点消失，任务进入可交付。
- 胜利后能看到基础剑法熟练度提升日志。
- 暂退后返回地图，强人触发点仍在。
- 存档后继续游戏，气血、背包和熟练度保持正确。

## 验收标准

本阶段完成后，玩家应能在山道强人战中进行多回合操作：用基础剑法攻击、承受敌人反击、必要时使用小还丹、选择暂退或取得胜利。胜利后回到地图，山道试剑可以继续交付，并记录基础剑法熟练度提升。

验收标准不是完整战斗系统，而是证明当前 RPG 框架已经具备可扩展的回合战斗核心、战斗中物品使用、胜负回流和武学成长存档。

## 实现约束

- 所有玩家可见文本必须使用中文。
- 代码标识符、Godot API、路径、配置键和命令可以保留英文。
- 不引入外部插件。
- 不把 Godot 引擎二进制提交到仓库。
- 逻辑优先写测试，再实现。
- 战斗规则必须有测试覆盖。
- 战斗界面只负责展示和接线，不承载长期战斗规则。
- `InventorySystem` 是消耗品使用的唯一规则入口。
- `.superpowers/`、`.tools/` 和 `.spec-workflow/` 不纳入提交。
