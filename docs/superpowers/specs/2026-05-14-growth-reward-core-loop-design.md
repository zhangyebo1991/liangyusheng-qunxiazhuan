# 成长与奖励闭环设计

## 背景

当前游戏已经具备地图切换、任务与对白、效果系统、商店与背包、江湖记事、战棋战斗、武学熟练度、队友和装备基础闭环。下一阶段需要补齐长期 RPG 推进反馈：玩家为什么继续战斗、完成任务、培养队友，以及这些行为如何稳定转化为角色成长。

本阶段目标是建立“战斗/任务 -> 奖励 -> 经验 -> 升级 -> 属性提升 -> UI 可见”的基础闭环。范围保持垂直可玩，不引入随机掉落表、复杂养成 UI、评分统计或职业转职。

## 目标

- 每个队友拥有独立等级、经验和累计经验。
- 战斗胜利和任务完成能够发放经验奖励。
- 角色升级按数据表成长，并在升级后完全回满气血和内力。
- 最终属性由角色模板、等级成长和装备加成统一合成。
- 战斗胜利显示轻量结算面板，展示经验、升级、铜钱和物品奖励。
- 队伍面板显示等级、经验进度和升级后的最终属性。
- 存档兼容旧数据，旧存档成员默认 1 级 0 经验。

## 非目标

- 不做随机掉落概率、保底、稀有度或掉落池。
- 不做手动属性点分配。
- 不做复杂升级动画、伤害统计、评分、战斗报告分页。
- 不做职业、天赋、突破、装备强化或武学学习 UI。
- 不重做现有战棋行动、武学熟练度或装备系统。

## 核心规则

成长粒度为每个队友独立等级和经验。战斗是主要经验来源，任务是辅助经验来源。

战斗胜利时，所有参战的玩家队友获得经验。第一版不区分存活、倒地或击杀贡献，只要该队友作为玩家单位进入战斗，就能获得本场经验。战斗失败不发经验和奖励，避免通过失败循环刷成长。

升级可连续多级。角色升级后按成长表提升基础属性，并完全回满当前气血与内力。这个规则让升级反馈清晰，也能减少早期资源压力。

## 数据设计

`PartyState.member_status` 扩展成员长期状态：

```gdscript
{
  "level": 1,
  "exp": 0,
  "total_exp": 0,
  "hp": 120,
  "mp": 20
}
```

`level` 是当前等级，`exp` 是当前等级内经验，`total_exp` 是累计经验。旧存档缺少这些字段时补默认值：`level=1`、`exp=0`、`total_exp=0`。

`actors.json` 增加成长配置：

```json
"growth": {
  "exp_curve": [0, 30, 80, 150],
  "per_level": {
    "max_hp": 8,
    "max_mp": 2,
    "attack": 1,
    "defense": 1
  }
}
```

`exp_curve` 使用累计经验曲线。数组第一个元素对应 1 级所需累计经验 0，第二个元素对应升到 2 级所需累计经验，以此类推。超过曲线末尾时视为达到当前数据表支持的最高等级。

战斗触发对象支持固定胜利奖励：

```json
"victory_rewards": {
  "exp": 20,
  "coins": 15,
  "items": [
    {"item_id": "herb_small", "amount": 1}
  ]
}
```

任务完成继续使用 `complete_effects`，新增效果类型：

```json
{"type": "add_party_exp", "amount": 10}
```

`add_party_exp` 给当前队伍所有成员发放经验。第一版不支持按角色单独配置任务经验。

## 系统设计

### GrowthSystem

新增 `scripts/systems/growth_system.gd`，作为经验和升级规则的单一入口。

职责：

- 读取角色成长配置。
- 给单个成员或全队发放经验。
- 计算连续升级。
- 返回升级结果，包含获得经验、旧等级、新等级、是否升级、提升的属性。
- 在升级时更新成员状态，并回满 HP/MP。

不负责：

- UI 展示。
- 战斗胜负判断。
- 物品和铜钱发放。
- 装备属性计算。

### ActorStatsSystem

`ActorStatsSystem` 继续作为最终属性单一来源。它在现有“角色模板 + 装备加成”基础上加入等级成长加成：

```text
最终属性 = 角色模板基础属性 + 等级成长加成 + 装备加成
```

当前 HP/MP 来自 `PartyState.member_status`，并 clamp 到成长和装备后的最大值。

### EffectSystem

新增 `add_party_exp` 效果。任务完成时可以通过这个效果给全队经验，并返回经验和升级结果供消息或测试使用。

`EffectSystem` 不直接计算成长细节，只调用 `GrowthSystem`。

### 战斗结算

`TacticalCombatSystem` 或战斗上下文在结果里携带本场参战玩家成员和固定 `victory_rewards`。`GameState.apply_battle_result()` 在胜利时处理奖励：

- 给参战队友发经验。
- 发放固定物品。
- 发放固定铜钱。
- 保留奖励结果，供 `BattleScreen` 胜利结算面板展示。

失败时不发经验、铜钱和物品。

### 胜利结算面板

`BattleScreen` 增加轻量胜利结算面板。面板展示：

- 每个参战队友获得的经验。
- 升级提示，例如“云游少侠 升至 2 级”。
- 升级后 HP/MP 回满提示。
- 铜钱奖励。
- 物品掉落明细。
- “返回地图”按钮。

第一版不做动画、评分、伤害统计、翻页或随机掉落表现。

### 队伍面板

`PartyPanel` 在队友详情中显示：

- 等级。
- 当前等级经验进度，例如 `经验 18/50`。
- 气血、内力、攻击、防御、移动、攻击距离等最终属性。
- 武器、衣甲、饰品。

队伍面板不直接计算成长，只读取 `ActorStatsSystem` 和成员状态。

## 错误处理

- 角色缺少成长配置时使用默认曲线 `[0]` 和空成长增量，表示暂不升级。
- 经验奖励小于等于 0 时不产生升级，返回成功但无变化，避免任务配置中断流程。
- 战斗奖励物品不存在时沿用当前奖励系统的保守策略：记录错误并不崩溃。
- 成员不在队伍中时不发经验。
- 旧存档成员状态缺等级经验字段时自动补齐默认值。

- `test_tactical_party_battle.gd`：覆盖战斗胜利经验奖励、失败不发奖励。
- `test_battle_screen_reward_panel.gd`：覆盖胜利结算面板展示经验、升级、铜钱和物品奖励。
- `test_party_panel.gd`：覆盖队伍面板显示等级、经验进度和成长后属性。
- 全量 `tests/run_tests.gd` 保持通过。

## 手动验收

1. 新游戏后完成山道试剑，青衫客入队。
2. 打赢一场战棋，胜利结算面板显示参战队友经验和固定奖励。
3. 经验足够时角色升级，结算面板显示升级提示。
4. 升级后按 `P` 打开队伍面板，等级、经验和属性更新。
5. 升级后 HP/MP 显示为满值。
6. 存档退出后重新进入，等级、经验、HP/MP 和装备保持正确。

## 风险与取舍

最大风险是经验、属性和装备三套数据同时影响角色最终战力。为降低风险，本阶段坚持 `ActorStatsSystem` 单一来源，不允许 UI 或战斗系统各自重复计算属性。

第二个风险是胜利结算面板会扩大 UI 范围。第一版只做文字和按钮，不做动画和复杂统计，确保阶段重点仍是成长闭环。

第三个风险是固定奖励与任务奖励语义重叠。第一版约定：战斗奖励写在 `victory_rewards`，任务奖励继续写在 `complete_effects`。两者都通过系统层发放，避免场景脚本直接改状态。
